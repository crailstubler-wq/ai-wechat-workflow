# ADLR 文档审查方法论

当你把工作流固化成文档（如本仓库的 `01`/`02`），文档会随时间**漂移**：步骤编号变了、规则前后矛盾、子 agent 拿不到关键定义。ADLR 是一套用来**审查工作流文档本身**的通用方法论，可作为你每次迭代后的自查工具。

> 提炼自真实审查实践（对 v7.4 主档 + 增强版 v0.3 的审查），去敏为通用框架。

---

## 1. 优先级（P1-P4）

| 级别 | 含义 | 处理 |
|------|------|------|
| **P1** | 业务对齐偏差 / 明显限制用户 | 需与用户交互确认，不可自行假设 |
| **P2** | 一致性残留 / 无记忆执行者缺口 | 直接修，影响可执行性 |
| **P3** | 措辞可能误导 / 实现细节越位 | 可修可不修，视整洁度 |
| **P4** | 辅助性、不应限制用户的内容 | 保持开放，不弱化为硬约束 |

---

## 2. 删除 / 修正判定（D1-D4）

| 判定 | 含义 | 动作 |
|------|------|------|
| **D1** | 完全无用的内容 | 删除 |
| **D2** | 无记忆执行者缺口（读到无法独立执行） | 补定义 / 补上下文 |
| **D3** | 重复定义 | 合并为单一权威源 |
| **D4** | 过时内容 | 更新到当前状态 |

---

## 3. 六条硬删规则（警惕这些「为圆逻辑而存在」的残留）

1. **防御性补丁** — 为解释旧错误而存在的说明，旧错误修了就该删。
2. **双源内联** — 同一规则在两处写、且一处带错字，删重复、留权威。
3. **实现细节越位** — 把工具调用方式混进业务知识，层级混乱，移走或删。
4. **为圆逻辑残留** — 旧表述（如「三件套」）与新规则（「两件套」）并存，删旧。
5. **元叙述** — 描述「为什么这样设计」的废话，非必要则删。
6. **临时注释** — 调试 / TODO 残留，发布前清掉。

---

## 4. 一致性清单（每次发版必查）

- [ ] 步骤编号 / 阶段数全文一致（如「八步」不能某处写「七步」）
- [ ] 同一概念只在一处权威定义（双源内联 = 风险）
- [ ] 子 agent 派发模板拿到了所有必要规则（无 D2 缺口）
- [ ] 版本记录段如实反映演进，非「为圆逻辑」保留
- [ ] 固定铁律（质量底线）未被弱化为「可配置」

---

## 5. 实战：用 ADLR 审查本仓库文档（去敏示例）

审查对象：`01-workflow-v7.4.md`（主档）+ `02-multi-agent-workflow.md`（增强版）。

| 编号 | 问题（类型） | ADLR 性质 | 修正 |
|------|------------|-----------|------|
| A1 | 「全自动」目标与实际多人工节点矛盾 | P1 业务对齐 | 改为「半自动（人工在选题/标题/推送确认）」 |
| A2 | 增强版漏 Step 8（主干已扩八步） | P2 关联影响 | 增强版补 Step 8 行 + 标题「七步」→「八步」 |
| B1 | 「结尾三件套」残留（已改两件套） | 为圆逻辑残留 / D4 | 改「两件套」 |
| B2 | 「四维评分」未定义四个维度 | D2 无记忆执行者缺口 | 补「时效/影响/契合/延展」 |
| B3 | 卡片配色两处定义且一带错字 | 双源内联 / D3 | 删重复、留权威 |
| B4 | 标题方法论未进派发模板 | D2 缺口 | 新增 §3.4 标题模板 |
| C1 | 沙箱调用方式混入业务知识 | 实现细节越位 / P3 | 移至踩坑或删 |
| C2 | 字数字段三处重复 | 双源内联 / D3 | 保留两处，余引用 |

**结论**：主干可独立执行，无致命错误；主要风险是**文档漂移**（编号/术语前后不一致）与**无记忆执行者缺口**（子 agent 拿不到关键定义）。这两类用 ADLR 一致性清单 + D2 判定即可在发版前堵住。

> 经验：工作流文档越是被「无记忆的子 agent」消费，越要把规则**显式化、单一源、可检查**——这正是 `02` §3 把品牌规范硬注入 prompt 的工程动机。
