# 公众号多 Agent 协作工作流（增强版）

> 含第一性原理约束与对抗式审查 · 基于 v8.0 八步流程（含 Step 6.5 预览 gate / Step 7 推送 / Step 8 评论巡查） · 2026-08-11 对齐 v8.0

---

## 0. 文档定位

本文是公众号 v8.0 工作流的 **agent 化封装 + 质量增强**，不替代原流程。

- **适用场景（三类风格桶，v8.0）**：桶2 观点共鸣风（嘴替心声，深度主题篇）/ 桶3 技术解读风（深度长文，低频周≤1篇）走完整多 agent 流程 + 红队；桶1 热点追踪风（事件驱动）通常主理人直写或单派 copywriter 更快，除非需红队事实核查。
- **不适用（主理人直写更快）**：桶1 日常热点轻量文（3000-3500 字，khazix 母规范直写即可）
- **与 AiContentCreatorTeam 的关系**：本文是专家团「预设 Workflow」之外、针对本公众号定制的**专属 Workflow**（可理解为 Workflow 7）。正式协作仍必须走专家团铁律（建团→派发→中转→回传）。

**质量增强的两根支柱**：
1. **第一性原理约束**——从一手信源 / 可验证事实出发，不用类比套话糊弄。
2. **对抗式审查（红队）**——正式加一个「挑刺环节」，在出文后、汇编前堵住事实 / 逻辑 / 品牌 / 读者反驳 / 完整性五类漏洞。

## 1. 团队协作铁律（必须走正式流程）

1. 主理人（司远 / Soren）**亲自** `TeamCreate`，命名 `ai-content-creator-<日期>-<选题简称>`，明确本次边界与上下文。团队创建严禁委派成员。
2. 按阶段派发成员 → 成员回传 → 主理人中转给下一阶段。**禁止成员互相直连**。
3. 子任务命名 `name` 与 `subagent_type` 必须传 Agent ID（`copywriter` / `image-creator`），禁止省略或用中文名。
4. **成员结论为准**：任何专业产出由对应成员输出后再采信，主理人只编排汇编，**禁止代写**。
5. 超时：成员超 10 分钟未回传，主理人主动通报；超 15 分钟视为失败，启动备选（主理人直写 / 换方案）。

## 2. 八步流程 → 角色映射

| 步骤 | 内容 | 执行方 | 说明 |
|------|------|--------|------|
| 1 选题采集 | WebSearch 热点 + 四维评分 | 主理人亲做 | 专家团无热点采集专长，且选题定调是工作流核心，不外派 |
| 2 写作设计 | 角度 / 类比 / 反差 / 情绪曲线 | 主理人亲做 | 策略层，品牌调性灵魂，不外派 |
| 3 标题方案 | A/B/C 三型 | 派 copywriter 初拟，主理人按三原则把关 | 标题质量三原则硬约束（信息密度 / 品牌辨识 / 情绪多样） |
| 4 撰写正文 | khazix / 技术解读长文 | 派 **copywriter** | 长文写作是其核心能力；必须注入 §3 派发模板 |
| 5 封面图 | 1280×720 横版 | 派 **image-creator** | 文生图完美适配；必须注入 §3.3 规范 |
| 6 HTML 排版 | 零 div 单 p 整块（微信兼容内联） | 主理人亲做 | 13 项防错 + 零 div 单 p（background 写 p + `<br>`），成员无此专长，不外派 |
| 7 推送 | 脚本 + IP 白名单 | 主理人亲做 | 技术脚本 `scripts/publish/wechat_push.py` |
| 8 发布后评论巡查 | 读者反馈对账（四级判定） | 主理人亲做 | Step 7 群发后固定动作，不阻塞 1-7；详见 v8.0 Step 8 |

> 轻量文（khazix 3000 字）可压缩为：主理人选题→写作设计→直写→HTML→推送，不开团。只有技术解读 / 深度长文才走完整 §4 红队流程。

## 3. 派发 Prompt 模板（含第一性原理约束）

> 子 agent **没有 working_memory 访问权**。所有品牌规范、风格铁律、第一性原理约束**必须显式写进派发 prompt**，否则 copywriter 会按通用长文风格写（冒号、双引号、套话全回来）。

> **风格桶硬标注（v8.0 根因修复）**：派发 copywriter 时 prompt 必须显式标【桶X】+ 对应范式，否则默认套 khazix 母规范会串味（8/4 国标篇因"桶分写法没分"导致 5 处翻案句未清、返工）。三类映射到本 Workflow：
> - **桶1 热点追踪风** → 客观陈述为主、硬禁翻案句、用媒体原口径（3000-3500 字）
> - **桶2 观点共鸣风（嘴替心声）** → 你视角 / 三拍结构（痛诉30-40%→翻转50-60%→钉句独立成行）/ 14-16 金句每句含具体物件（3000-3500 字）
> - **桶3 技术解读风** → 不用 khazix、客观复盘、信源一手（4000-6000 字，≤1 篇/周）
> 下文 §3.1 覆盖桶1+桶2（khazix 母规范），§3.2 覆盖桶3。

### 3.1 copywriter 派发模板（观点型 · khazix · 覆盖桶1+桶2）

```
你是本公众号「六一的AI人生记录仪」的专栏撰稿人。请基于以下选题撰写一篇公众号长文。

【风格桶 · 必填】二选一标注：
- 桶1 热点追踪风：客观陈述为主，硬禁翻案句（check_prose 翻案句必须清零），用媒体原口径，少第一人称强判断
- 桶2 观点共鸣风（嘴替心声）：全篇"你"视角，三拍结构（痛诉30-40%→翻转50-60%→钉句独立成行），金句密度14-16句每句含具体物件/动作，先痛诉后判断

【选题】
<选题标题 + 三塔类型（流量/人设/转化）+ 核心角度（第4个反差点）>

【品牌人格】
AI 行业干了多年的老朋友，懂行但不端着，有观点但不强加，敢说真话。爱喝茶爱琢磨。

【写作风格铁律 · khazix】
- 禁用中文冒号「：」、破折号「——」、英文冒号
- 禁用双引号，改用「」书名号式引号
- 禁用套话：说白了 / 意味着 / 本质上 / 毋庸置疑 / 众所周知 等
- 不设小标题，段落短（3-5 行），节奏自然，第一人称对话式
- 必须输出个人观点，不能只堆事实
- **桶1 热点追踪**：客观陈述为主，硬禁翻案句（"和很多人直觉相反""我得把话说死"类强判断清零），用媒体原口径，personal view 仅限收尾一段
- **桶2 观点共鸣（嘴替心声）**：人称从"我观察"翻成"我和你都被卡住"，开篇禁资历自述、重设钩子；金句拉高到14-16句；安全章（如涉及）做成最扎心压轴（先扎透再翻转），禁爽文句

【第一性原理约束（硬规则）】
1. 每条核心论断必须能追溯到一手信源或可验证事实；文末单列「信源」段
2. 禁止用类比替代论证（偷懒）。生活化类比仅可用于「帮助理解」，且论证主体须在别处用事实完成
3. 数据 / 事件若有时点、主体、出处，必须写清，零编造

【输出要求】
- 字数纯汉字 ≥ 3000（用 sed 's/[[:space:][:punct:]]//g' | wc -m 确认）
- 开场 3 段内必须建立悬念，不能以事实堆砌开头
- 结尾两段：一段个人态度收束，一段轻触点「记录AI时代的每天」品牌口号
- 输出纯 Markdown（不含 HTML），文件名 article.md
```

### 3.2 copywriter 派发模板（技术解读型 · 第四支柱 · 桶3）

```
你是本公众号「六一的AI人生记录仪」的技术专栏撰稿人。请基于以下选题撰写一篇技术解读长文。

【选题】
<技术事件 + arXiv/官方博客一手信源链接 + 关键数据>

【定位 · 桶3 技术解读风】
第四内容支柱「技术解读」：客观复盘风、第三方视角，低频（周≤1篇）。
不用 khazix 母规范（允许正常标点/分点/小标题），开头结尾轻触品牌人格（六一老朋友调性），别写成纯论文。

【写作风格】
- 允许正常标点、分点、小标题、引用（与 khazix 不同）
- 客观复盘，不强行情绪钩子，但标题 / 正文须含「主体 + 判断 + 品牌辨识」

【第一性原理约束（硬规则 · 技术解读版）】
1. 必须引用一手信源（arXiv / 官方博客），零编造技术细节；文末单列「信源」段含链接
2. 每个技术论断（机制 / 数据 / 结论）必须可追溯到信源原文，禁止「据传 / 可能 / 大概」
3. 禁止用类比替代机制解释；类比仅作辅助

【结构模板（必须齐全）】
背景 → 方法/机制拆解 → 技术细节（可配浅色「技术说明框」） → 行业启示 → 总结
开头结尾轻触品牌人格。

【输出要求】
- 字数 4000-6000（含标点）
- 结尾两件套由主理人后续组装，你只需在文末留空行
- 输出纯 Markdown，文件名 article.md
```

### 3.4 copywriter 标题派发模板（标题方案）

```
你是本公众号「六一的AI人生记录仪」的标题策划。请基于以下选题产出标题方案。

【选题】
<选题标题 + 三塔类型（流量/人设/转化）+ 核心角度>

【标题质量三原则（硬约束）】

2. 用三原则收敛到 A/B/C 三型（各 1 个）交主理人，由用户拍板
3. 公式池只扩思路，不堆 30 个让用户选

【输出】标题方案文本（A/B/C 三型 + 每型一句话理由）
```

## 4. 第一性原理约束（硬规则总览）

**定义**：从一手信源和可验证事实出发推导，不用类比和套话替代论证。

本公众号工作流已有雏形：技术解读第四支柱要求「必须引一手信源、零编造」；khazix 禁套话。多 agent 化后用 §3 模板把约束**显式化、可检查**。

三条硬规则（适用于所有类型）：
1. **信源锚定**：每条核心论断可追溯到一手信源或可验证事实，文末列「信源」段。
2. **类比节制**：禁止用类比替代论证（偷懒）；生活化类比仅用于帮助理解，且论证主体已在别处用事实完成。
3. **零套话**：禁止「说白了 / 意味着 / 本质上 / 毋庸置疑 / 众所周知」等填充式概括。

> 度要写清：完全禁类比会牺牲非技术读者的可读性，所以禁的是「用类比替代论证」，不是「用类比帮助理解」。

## 5. 对抗式审查（红队）环节

**触发条件**：技术解读篇 / 深度长文 **默认开**；轻量文可跳过。

### 5.1 执行方

- **默认：主理人亲自做**（领域上下文——暗线连续剧、微信 API 细节、品牌暗线——不外泄给通用 agent，避免红队抓错重点或「为挑刺而挑刺」）。
- **可选**：技术解读重事实篇，可派第二个 `copywriter` 实例做红队，**但必须注入完整信源上下文**（arXiv 链接、关键数据），否则它无法判断事实真伪。

### 5.2 五维审查清单

| 维度 | 审查点 |
|------|--------|
| ① 事实准确性 | 信源是否一手、数据是否准确、有无编造或夸大、时点主体是否写清 |
| ② 逻辑自洽 | 论点是否自相矛盾、因果是否成立、有没有「前面说 A 后面说非 A」 |
| ③ 品牌调性 | khazix / 技术解读风格是否跑偏、三塔类型是否相符、标题三原则（信息密度/品牌辨识/情绪多样） |
| ④ 读者反驳点 | 目标读者会怎么杠、是否堵住；有无认知盲区；情绪是否连续否定型（同型标题要换角度） |
| ⑤ 完整性 | 技术解读五段结构齐不齐、是否漏关键视角、与暗线连续剧（框架裸奔→信错人→自己人开枪→看门人换AI）的衔接 |

### 5.3 《审查报告》输出模板

```
【红队审查报告 · <选题>】
事实准确性：<通过 / 存疑点列表>
逻辑自洽：<通过 / 矛盾点>
品牌调性：<通过 / 偏离点>
读者反驳点：<读者会怎么杠 + 是否堵住>
完整性：<缺漏项>
【必须修订项】<逐条列出，copywriter 据此出 v2>
【可选优化项】<锦上添花>
```

### 5.4 修订闭环

copywriter 据《审查报告》修订 → 输出 `article_v2.md` → 主理人确认 → 进入 §6 最终阀。若修订后仍有硬伤，主理人亲自改或打回再修。

## 6. 主理人最终质量阀（13 项防错 · v8.0 口径）

在所有成员回传后、推送前，主理人亲自收口：

1. **L1-L4 自检**（文字关）
   - L1 禁标点（桶1/桶2/khazix：零冒号 / 零破折号 / 零双引号；桶3 技术解读允许正常标点）
   - L2 字数（桶1/桶2 ≥ 3000 纯汉字，桶3 4000-6000 含标点）
   - L3 角度反差（第4个反差点是否成立）
   - L4 情绪曲线（忌连续否定型标题）
2. **排版 13 项防错**（由原「HTML 八项微信兼容检查」扩展而来，对齐 v8.0）：
   - ① 零 div：色块一律单 p 整块（background/border/padding 写在 p + `<br>` 换行），禁 div 背景（8/5-8/6 div 翻车根因）
   - ② 仅 1 个外层 `<section>` 容器（居中 max-width:680px），禁嵌套 section
   - ③ 全内联样式；无 class / DOCTYPE / 注释 / flex / gradient / ul-li / grid
   - ④ 卡片配色按语义（浅橙 #fffaf0+金边 / 浅蓝 #f0f7ff+蓝边 / 浅红 #fff5f5+红边 / 浅绿 #f0fff4+绿边），深色仅结尾两件套 #1a1a2e+金边 #f5a623
   - ⑤ 结尾两卡（写在最后 + 关注我）**p 必须带 color:#e8e8e8**，金色标题（关注我居中，第二行固定「六一的 AI 人生记录仪」）
   - ⑥ check_prose 全 0（翻案句 / 黑话 / 模型路标清零；桶1 热点追踪硬禁翻案句）
   - ⑦ 重复标题检查：删 article.html 首个 22px bold p（微信已用 metadata.title 渲染头条，正文再放即撞车；8/10 踩坑）
   - ⑧ 日期 grep 零命中（时间线正确）、禁 khazix 自称、禁自我引用（"我这号/本号/号主"清理）、二手无拟人化
3. **结尾两件套铁律**：写在最后 + 关注我（深色卡 #1a1a2e + 金边 #f5a623，关注我整块居中）；**关注我卡不挂外链**，靠 `wechat_push.py` 自动追加公众号名片。
4. **封面图预览确认**再上传（先预览确认再 cp 为 cover.png）。
5. **Step 6.5 预览 gate（硬，不可省）**：排版后必 present_files 预览 + 列层次清单，用户核对 OK 才进 Step 7 推送。

## 7. 边界与坑（必读）

1. **红队别随便派通用 agent**：它不懂暗线连续剧、不懂微信 API。派红队必须注入完整领域上下文，否则抓错重点。
2. **第一性原理禁过度**：非技术读者需要类比助理解，约束是「禁替代论证」不是「禁一切类比」。
3. **耗时权衡**：多一轮红队中转，日更轻量文不值当——轻量文主理人快速自检即可，只有低频深度篇才开团 + 红队。
4. **copywriter 默认通用长文风**：规范必须显式注入 prompt，否则冒号 / 双引号 / 套话全回来。
5. **子 agent 无 working_memory**：品牌规范全靠 prompt 注入，不能依赖它「记得」之前的约定。
6. **IP 白名单 + 清代理（8/7 踩坑）**：推送前 `env -u HTTPS_PROXY -u HTTP_PROXY -u https_proxy -u http_proxy NO_PROXY="*"` 清代理，否则会被本地代理拦截；IP 白名单需加段防 NAT 轮换（微信识别 ::ffff: 映射，出口 IP 漂移会被拒），预留用户后台加白名单时间。
7. **主 Agent 瓶颈（中转损耗）**：本 Workflow 本质是「主理人（主 Agent）统筹 + copywriter/image-creator（Sub-Agent）执行」，正是行业文批判的「主 Agent + Sub-Agent」结构。场景不同（内容生产非解题，主理人中转是品牌阀 / 质量阀必需），但风险真实——中转每多一轮就有一次理解损耗。对抗机制已内置：① §3 派发模板把品牌规范 / 第一性原理**硬注入 prompt**，减少成员「猜意图」带来的损耗；② §5 红队审查在出文后堵逻辑 / 事实 / 品牌漏洞。参考外部文：阿颖 AI产品《很久没读过这么通透的Agent的文章了》解析 EvoMap（Sub-Agent 中间答对 373 道、主 Agent 汇总后仅留 217 道，损耗 44.5%）。
8. **重复标题（8/10 踩坑）**：article.md 开头的 `# 标题` 会被 md→html 渲染成首个 22px bold p，与微信后台用 metadata.title 渲染的头条撞车，正文出现两次标题。推送前必须删 article.html 首个 22px bold p；或排版脚本加自动后处理。
9. **翻案句 / 桶分写法（8/4 国标篇返工根因）**：桶1 热点追踪风的事件文若套 khazix 母规范的强判断写法，会与 check_prose 翻案句清零冲突（5 处翻案句未清）。派 copywriter 必标【桶X】，桶1 显式加「硬禁翻案句、客观陈述为主」。
10. **Step 6.5 预览 gate 不可省**：排版后必须 present_files 预览并请用户核对，否则重复标题 / 配色错漏类问题会漏到线上。
