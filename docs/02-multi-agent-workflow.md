# 公众号多 Agent 协作工作流（增强版 v0.3）

> 含第一性原理约束与对抗式审查 · 基于 v7.4 八步流程（含 Step 8 发布后评论巡查） · 2026-07

> **去敏说明**：本文档为通用方法论。文中 `<公众号名称>`、`<WECHAT_ID>` 等为占位符，请替换为你的实际值。派发模板中的品牌人格 / Slogan 仅作示例，可改为你自己的调性。

---

## 0. 文档定位

本文是公众号 v7.4 工作流的 **agent 化封装 + 质量增强**，不替代原流程。

- **适用场景**：技术解读第四支柱篇、深度长文（低频，周 ≤ 1 篇）。
- **不适用（主理人直写更快）**：日常轻量文。
- **与专家团的关系**：本文是专家团「预设 Workflow」之外、针对本公众号定制的专属 Workflow。正式协作仍必须走专家团铁律（建团 → 派发 → 中转 → 回传），见 `docs/03`。

**质量增强的两根支柱**：

1. **第一性原理约束** — 从一手信源 / 可验证事实出发，不用类比套话糊弄。
2. **对抗式审查（红队）** — 正式加一个「挑刺环节」，在出文后、汇编前堵住事实 / 逻辑 / 品牌 / 读者反驳 / 完整性五类漏洞。

---

## 1. 团队协作铁律（必须走正式流程）

1. 主理人**亲自** `TeamCreate`，命名 `ai-content-creator-<日期>-<选题简称>`，明确本次边界与上下文。团队创建严禁委派成员。
2. 按阶段派发成员 → 成员回传 → 主理人中转给下一阶段。**禁止成员互相直连**。
3. 子任务命名 `name` 与 `subagent_type` 必须传 Agent ID（如 `copywriter` / `image-creator`），禁止省略或用中文名。
4. **成员结论为准**：任何专业产出由对应成员输出后再采信，主理人只编排汇编，**禁止代写**。
5. 超时：成员超 10 分钟未回传，主理人主动通报；超 15 分钟视为失败，启动备选（主理人直写 / 换方案）。

## 2. 八步流程 → 角色映射

| 步骤 | 内容 | 执行方 | 说明 |
|------|------|--------|------|
| 1 选题采集 | 热点 + 四维评分 | 主理人亲做 | 专家团无热点采集专长，选题定调不外派 |
| 2 写作设计 | 角度 / 类比 / 反差 / 情绪曲线 | 主理人亲做 | 策略层，品牌调性灵魂，不外派 |
| 3 标题方案 | A/B/C 三型 | 派 copywriter 初拟，主理人按三原则把关 | 标题质量三原则硬约束 |
| 4 撰写正文 | 长文（双文风） | 派 **copywriter** | 必须注入 §3 派发模板 |
| 5 封面图 | 1280×720 横版 | 派 **image-creator** | 必须注入 §3.3 规范 |
| 6 HTML 排版 | 微信兼容内联 | 主理人亲做 | 私有标签 / 8 项兼容检查，不外派 |
| 7 推送 | 脚本 + IP 白名单 | 主理人亲做 | 技术脚本（读 `metadata.json`） |
| 8 发布后评论巡查 | 读者反馈对账（四级判定） | 主理人亲做 | Step 7 群发后固定动作，不阻塞 1-7 |

> 轻量文可压缩为：主理人选题 → 写作设计 → 直写 → HTML → 推送，不开团。只有技术解读 / 深度长文才走完整 §5 红队流程。

## 3. 派发 Prompt 模板（含第一性原理约束）

> 子 agent **没有工作记忆访问权**。所有品牌规范、风格铁律、第一性原理约束**必须显式写进派发 prompt**，否则会按通用长文风格写（冒号、双引号、套话全回来）。

### 3.1 copywriter 派发模板（观点型）

```
你是本公众号「<公众号名称>」的专栏撰稿人。请基于以下选题撰写一篇公众号长文。

【选题】
<选题标题 + 三塔类型（流量/人设/转化）+ 核心角度（第4个反差点）>

【品牌人格】
AI 行业干了多年的老朋友，懂行但不端着，有观点但不强加，敢说真话。

【写作风格铁律】
- 禁用中文冒号「：」、破折号「——」、英文冒号
- 禁用双引号，改用「」书名号式引号
- 禁用套话：说白了 / 意味着 / 本质上 / 毋庸置疑 / 众所周知 等
- 不设小标题，段落短（3-5 行），节奏自然，第一人称对话式
- 必须输出个人观点，不能只堆事实

【第一性原理约束（硬规则）】
1. 每条核心论断必须能追溯到一手信源或可验证事实；文末单列「信源」段
2. 禁止用类比替代论证（偷懒）。生活化类比仅可用于「帮助理解」，且论证主体须在别处用事实完成
3. 数据 / 事件若有时点、主体、出处，必须写清，零编造

【输出要求】
- 字数纯汉字 ≥ 3000（用 sed 's/[[:space:][:punct:]]//g' | wc -m 确认）
- 开场 3 段内必须建立悬念，不能以事实堆砌开头
- 结尾两段：一段个人态度收束，一段轻触点品牌口号
- 输出纯 Markdown（不含 HTML），文件名 article.md
```

### 3.2 copywriter 派发模板（技术解读型 · 第四支柱）

```
你是本公众号「<公众号名称>」的技术专栏撰稿人。请基于以下选题撰写一篇技术解读长文。

【选题】
<技术事件 + 一手信源链接（如 arXiv/官方博客） + 关键数据>

【定位】
第四内容支柱「技术解读」：客观复盘风、第三方视角，低频（周≤1篇）。
开头结尾轻触品牌人格，别写成纯论文。

【写作风格】
- 允许正常标点、分点、小标题、引用（与观点型不同）
- 客观复盘，不强行情绪钩子，但标题 / 正文须含「主体 + 判断 + 品牌辨识」

【第一性原理约束（硬规则 · 技术解读版）】
1. 必须引用一手信源（arXiv / 官方博客），零编造技术细节；文末单列「信源」段含链接
2. 每个技术论断必须可追溯到信源原文，禁止「据传 / 可能 / 大概」
3. 禁止用类比替代机制解释；类比仅作辅助

【结构模板（必须齐全）】
背景 → 方法/机制拆解 → 技术细节（可配浅色「技术说明框」） → 行业启示 → 总结

【输出要求】
- 字数 4000-6000（含标点）
- 输出纯 Markdown，文件名 article.md
```

### 3.3 image-creator 派发模板（封面图）

```
为本公众号文章生成一张封面图。

【规格】1280×720 横版，16:9，无文字水印、不含任何品牌 logo。
【风格】深海科技质感：深海军蓝 #1a1a2e 主色 + 金色 #f5a623 点缀，清爽留白。
【构图】<根据选题描述具体构图、主体、色调>
【提示词语言】必须英文
【输出】生成后主理人会 cp 为 cover.png 用于推送
```

### 3.4 copywriter 标题派发模板（标题方案）

```
你是本公众号「<公众号名称>」的标题策划。请基于以下选题产出标题方案。

【选题】
<选题标题 + 三塔类型 + 核心角度>

【标题质量三原则（硬约束）】
1. 信息密度——必须含主体+判断，读者扫一眼知道讲什么
2. 品牌辨识——有从业者视角、有态度、敢说真话
3. 情绪多样——不连续否定型；同型标题也要换角度

【产出方式】
1. 先用 10 类通用公式各出 2-3 个标题扩成素材池：①结果承诺 ②问题解决 ③悬念好奇 ④反差对比 ⑤利益点 ⑥权威/数据 ⑦观点态度 ⑧警示威胁 ⑨身份共鸣 ⑩场景代入
2. 用三原则收敛到 A/B/C 三型（各 1 个）交主理人，由用户拍板
3. 公式池只扩思路，不堆 30 个让用户选

【输出】标题方案文本（A/B/C 三型 + 每型一句话理由）
```

## 4. 第一性原理约束（硬规则总览）

**定义**：从一手信源和可验证事实出发推导，不用类比和套话替代论证。

三条硬规则（适用于所有类型）：

1. **信源锚定**：每条核心论断可追溯到一手信源或可验证事实，文末列「信源」段。
2. **类比节制**：禁止用类比替代论证（偷懒）；生活化类比仅用于帮助理解，且论证主体已在别处用事实完成。
3. **零套话**：禁止「说白了 / 意味着 / 本质上 / 毋庸置疑 / 众所周知」等填充式概括。

> 度要写清：完全禁类比会牺牲非技术读者的可读性，所以禁的是「用类比替代论证」，不是「用类比帮助理解」。

## 5. 对抗式审查（红队）环节

**触发条件**：技术解读篇 / 深度长文 **默认开**；轻量文可跳过。

### 5.1 执行方

- **默认：主理人亲自做**（领域上下文——暗线连续剧、平台 API 细节、品牌暗线——不外泄给通用 agent，避免红队抓错重点或「为挑刺而挑刺」）。
- **可选**：技术解读重事实篇，可派第二个 `copywriter` 实例做事实核查红队，**但必须注入完整信源上下文**（链接、关键数据），否则它无法判断事实真伪。

### 5.2 五维审查清单

| 维度 | 审查点 |
|------|--------|
| ① 事实准确性 | 信源是否一手、数据是否准确、有无编造或夸大、时点主体是否写清 |
| ② 逻辑自洽 | 论点是否自相矛盾、因果是否成立、有没有「前面说 A 后面说非 A」 |
| ③ 品牌调性 | 文风是否跑偏、三塔类型是否相符、标题三原则 |
| ④ 读者反驳点 | 目标读者会怎么杠、是否堵住；有无认知盲区 |
| ⑤ 完整性 | 结构齐不齐、是否漏关键视角、与暗线连续剧的衔接 |

### 5.3 《审查报告》输出模板

```
【红队审查报告 · <选题>】
事实准确性：<通过 / 存疑点列表>
逻辑自洽：<通过 / 矛盾点>
品牌调性：<通过 / 偏离点>
读者反驳点：<读者会怎么杠 + 是否堵住>
完整性：<缺漏项>
【必须修订项】<逐条列出，copywriter 据此出 v2>
【可选优化项】<锦上添花>
```

### 5.4 修订闭环

copywriter 据《审查报告》修订 → 输出 `article_v2.md` → 主理人确认 → 进入 §6 最终阀。若修订后仍有硬伤，主理人亲自改或打回再修。

---

## 6. 主理人最终质量阀

在所有成员回传后、推送前，主理人亲自收口：

1. **L1-L4 自检** — L1 禁标点（观点型：零冒号 / 零破折号 / 零双引号）；L2 字数（区间见 §3.1/§3.2）；L3 角度反差（第4个反差点是否成立）；L4 情绪曲线（忌连续否定型标题）。
2. **HTML 八项微信兼容检查**：无 class / flex / grid / ul-li / DOCTYPE 等；全内联样式；卡片配色按语义（浅蓝/浅红/浅橙/浅绿，深色仅结尾两件套）。
3. **结尾两件套铁律**：写在最后 + 关注我（深色卡 + 金边，关注我整块居中）；**关注我卡不挂外链**，靠推送脚本自动追加公众号名片。
4. **封面图预览确认**再上传。

## 7. 边界与坑（必读）

1. **红队别随便派通用 agent**：它不懂暗线连续剧、不懂平台 API。派红队必须注入完整领域上下文，否则抓错重点。
2. **第一性原理禁过度**：非技术读者需要类比助理解，约束是「禁替代论证」不是「禁一切类比」。
3. **耗时权衡**：多一轮红队中转，日更轻量文不值当——轻量文主理人快速自检即可，只有低频深度篇才开团 + 红队。
4. **copywriter 默认通用长文风**：规范必须显式注入 prompt，否则冒号 / 双引号 / 套话全回来。
5. **子 agent 无工作记忆**：品牌规范全靠 prompt 注入，不能依赖它「记得」之前的约定。
6. **IP 白名单动态轮换**：推送阶段可能卡 IP（平台识别 `::ffff:` 映射），预留用户后台加白名单的时间。
7. **主 Agent 瓶颈（中转损耗）**：本 Workflow 本质是「主理人（主 Agent）统筹 + Sub-Agent 执行」结构。中转每多一轮就有一次理解损耗。对抗机制已内置：① §3 派发模板把品牌规范 / 第一性原理**硬注入 prompt**，减少成员「猜意图」损耗；② §5 红队审查在出文后堵逻辑 / 事实 / 品牌漏洞。

---

## 8. 与现有脚本的关系

- 单 agent 时代的提示词基底（写作 / 审稿）可复用其骨架。
- 多 agent 化后：copywriter 派发 prompt = 写作提示词基础上加 §4 第一性原理约束；红队审查 = 审稿提示词基础上加 §5.2 五维对抗清单。
- 推送仍走独立脚本（自动追加名片、默认读 `cover.png`）。
