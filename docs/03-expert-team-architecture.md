# AI 内容创作专家团架构（实战案例）

本文以「AI 内容创作专家团」为样板，讲清楚一套可复用的**多 Agent 内容生产架构**：如何拆角色、如何建团协作、如何路由任务、以及一篇深度文如何跑通对抗式审查。

> 架构提炼自真实实践，去敏后可直接套用到你自己的内容生产场景。

---

## 1. 角色定位

主理人（创意制片人）统筹全流程，协调六类专业成员。主理人只做**编排、中转、汇编、质量收口**，**禁止代写**任何成员的专业产出。

| Agent ID | 名字 | 擅长领域 |
|----------|------|---------|
| `creative-strategist` | 策凌 | 品牌定位、情绪板、广告创意方向、场景构思、Logo 概念 |
| `copywriter` | 笔澜 | 长文（公众号/博客）、短文案（小红书/社媒）、视频脚本、营销文案、SEO |
| `image-creator` | 珀西 | 文生图、图生图 / 图片编辑、批量生成、平台尺寸适配 |
| `video-generator` | 维欧 | 文生视频、图生视频、人物视频、特效视频、视频 Prompt 工程 |
| `video-editor` | 柯立 | 视频裁剪/拼接/转场、字幕/水印、滤镜/动画、横竖屏转换 |
| `content-adapter` | 艾达 | 视频内容分析、精彩片段提取、视频翻译、多媒体合成、视频转文字 |

---

## 2. 协作铁律（不可妥协）

1. **团队必须主理人亲自建**：`TeamCreate` 只能主理人执行，严禁委派成员。
2. **成员回传 → 主理人中转**：所有跨成员信息流经主理人中转，**禁止成员互相直连**。
3. **成员结论为准**：专业产出由对应成员输出后再采信，主理人只编排汇编。
4. **子任务命名规范**：`name` 与 `subagent_type` 必须传 Agent ID（如 `copywriter`），禁止省略或用中文名。
5. **禁止行为**：跳过建团直接模拟成员发言 / 主理人代写 / 未完前序阶段跳后序 / 成员互连。

## 4. 预设 Workflow 概览

| # | Workflow | 触发条件 | 核心路径 |
|---|----------|---------|---------|
| 1 | 短视频生产 | 生成一段视频 | 关键帧(可选) → 视频生成 → 后期(可选) |
| 2 | 图文批量 | 一组图文 / 种草图 | 批量生图 → 审核 |
| 3 | 视频+图文混合 | 新品上市物料 | 图文 + 视频并行 → 后期 → 合成 |
| 4 | 视频翻译 | 多语言版本 | 翻译 → 加字幕 |
| 5 | 图文创作 | 写文章 + 配图 | 写文 → 配图(可选) |
| 6 | 视频脚本+视频 | 从文案到视频 | 脚本 → 关键帧 → 视频 → 拼接 |
| 7 | 创意策划+内容生产 | 品牌物料 / 不确定风格 | 策划 → 按方案调度 |
| 8 | 发布级精修 | 正式版 / 精确文字 | 策划 → 文案 → 精修合成 |

> 图生视频优先：无参考图且需求是视频时，优先「先生成关键帧 → 再图生视频」，质量与可控性通常优于纯文生视频。

## 5. 模型选型决策（平台内置工具）

| 需求 | 推荐模型 | 调度成员 |
|------|---------|---------|
| 文生视频（通用） | 平台视频模型 A | `video-generator` |
| 图生视频（通用） | 平台视频模型 B | `video-generator` |
| 图生视频（人物） | 平台人物视频模型 | `video-generator` |
| 图片特效视频 | 平台特效模板 | `video-generator` |
| 文生图（高质量） | 平台图像模型 A/B | `image-creator` |
| 文生图（快速） | 平台轻量图像模型 | `image-creator` |
| 图片编辑 | 平台图像编辑工具 | `image-creator` |
| 视频内容分析 | 平台多模态理解模型 | `content-adapter` |
| 视频翻译 | 声纹克隆 + 唇型同步 | `content-adapter` |
| 多素材合成 | 多媒体合成引擎 | `content-adapter` |
| 视频转文字 | 本地语音识别工具链 | `content-adapter` |

> 具体模型名随平台版本演进，请以你所用平台的当前内置工具清单为准。核心原则是**按任务类型路由到专长模型**，而非混用。

## 6. 实战案例：一篇技术解读如何跑通对抗审查

以「本地智能体沙箱逃逸」技术解读为例（低频深度篇，走 `docs/02` 增强流程）：

```
Phase A  选题+写作设计   主理人：四维评分选定 → angle.md 固化信源表+反差点
Phase B  撰写            copywriter：按 §3.2 技术解读模板出 article.md（4619 字）
Phase C  对抗式红队      content-adapter 事实核查层 + 主理人四维红队 → 合并《审查报告》
Phase D  修订            copywriter 据报告出 article_v2.md（3 处修订）
Phase E  排版+推送       主理人 HTML 排版（8 项兼容）→ 脚本建草稿 → 用户群发
Phase F  评论巡查        Step 8 四级框架对账（群发后 1-3 天）
```

**验证结论（回答「多 agent 能对抗审查吗」）**：

- **能，且有效**。三层独立视角各自抓到不同问题：事实层揪出信源口径疑点；主理人四维揪出事实层没覆盖的逻辑硬伤 + 读者反驳盲区；主编复核又驳回了事实层的一处误报。
- **但主编复核不可省**。任一 agent 的结论都不能盲信——本次实测中 copywriter 自报「纯汉字 3284」，用 `sed` 复核实为 4619，差近 1400 字，若信了自报就放过字数核查。
- **机制本质**：多 agent 提供对抗视角 + 主编独立核实 + 机器指标复核，三件套才站得住。

这套架构的价值不在「自动化」，而在**把质量阀从单个写手的自审，升级为多角色对抗 + 主编兜底**，特别适合低频、高事实密度、易被杠的深度内容。
