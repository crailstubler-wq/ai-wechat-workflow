# 写作风格指南 · 六一的 AI 人生记录仪

> 版本 v1.0（2026-08-11 从 agent.md v8.0 + MEMORY.md + article_template.html 固化）
> 用途：每日写文前**唯一对照表**。不再翻对话、不再凭记忆，照表执行即可，避免漏掉重点标记/可视化层次。
> 配套根模板：`templates/article_template.html`（排版前必 Read 对齐色值，禁每期自创格式）

---

## 0. 一句话总纲

公众号调性（专业不枯燥、有温度有观点，AI 行业老朋友人格）→ **每日现定题（不做选题池）** → **选题先定【桶】** → 三类桶各有独立写作范式（禁混写）→ 文案过 `check_prose` 硬 gate → HTML 走**零 div 单 p 整块 + 高密度可视化层次** → **13 项防错逐条过，不过不推**。

---

## 1. 运营节奏铁律（影响一切，先讲）

- **日更半自动**：AI 写/排/推草稿；人工负责：选题、标题拍板、IP 白名单、群发、配图。
- **不做长期选题池**（2026-08-11 用户拍板）：拒绝提前 2-4 周锁死排期。日更号追当日热点/情况，提前定死易过时、绑手脚（用户原话「不用做选题池，因为每天的情况都不一样」）。
- **每日现场定题**：据当日热点 + 三塔比例 + 风格桶，当天选题。
- **三塔配比**：流量 40%（拉新）/ 人设 30%（信任）/ 转化 30%（认知反转），不连续同类。

## 2. 三类风格桶（选题先定桶，再写 · 禁混写）

写作前必须先把文章归到以下一类，**派 copywriter 时 prompt 须显式标【桶X】+ 对应范式**，否则默认套 khazix 母规范导致串味（8/4 国标即因此翻车）。

| 桶 | 驱动 | 触发器 | 写作范式要点 | 字数 |
|----|------|--------|------------|------|
| **桶1 热点追踪风** | 事件驱动 | 具体发布/安全事件/政策；快出（热点生命周期 3-5 天） | 客观陈述为主 + 简短点评；用媒体原口径禁拟人化；可第一人称但不强出个人观点；**硬禁翻案句**；定语写全 + 标阶段 | 3000-3500 纯汉字 |
| **桶2 观点共鸣风（嘴替心声）** | 主题驱动 | 持续命题/行业判断，非事件，求共鸣 | 全篇「你」视角；三拍结构（痛诉 30-40% → 翻转 50-60% → 钉句独立成行）；金句 14-16 句含具体物件/动作；先痛诉后判断；开篇钩子禁资历自述 | 3000-3500 纯汉字 |
| **桶3 技术解读风** | 机制驱动 | 技术/机制深扒，非快讯 | 不用 khazix，客观复盘风；背景→机制→细节→启示→总结；信源一手零编造；禁第一人称观点前置 | 4000-6000 含标点（≤1 篇/周，第四支柱） |

### 各桶范式详述

**桶1 热点追踪风（事件驱动·流量 40%，主体 60+ 篇）**
- 范式：客观陈述为主 + 简短点评；用媒体原口径，禁拟人化演绎；可第一人称但不强出个人观点。
- **硬禁翻案句**（"和很多人直觉相反""我得把话说死"类强判断归桶2）；`check_prose` 翻案句须 0。
- 定语写全 + 标阶段（计划下达 ≠ 已实施）；时间线主宾不颠倒；事件日 ≠ 披露日。
- 占比主体，是最常用的桶。

**桶2 观点共鸣风（主题驱动·嘴替心声·人设 30% + 转化 30%）**
- 范式（8/10 org-reshape v2 沉淀为通用）：全篇「你」视角；三拍结构（痛诉 → 翻转 → 钉句独立成行）；金句密度 14-16 句且每句含具体物件/动作；先痛诉后判断；开篇钩子禁资历自述；安全章压轴扎透再翻转。
- 硬约束：`check_prose` 翻案句/黑话/模型路标须 0；禁 khazix 自称；金句须排布到位。
- 注：分析报告风（数据堆砌缺共鸣，org v1 被用户打回）不作独立桶存活。

**桶3 技术解读风（机制驱动·客观复盘·人设 30%）**
- 范式：不用 khazix，客观复盘风；背景 → 机制 → 细节 → 启示 → 总结；信源一手零编造。
- 硬约束：禁第一人称观点前置；禁翻案句；信源标注清晰。
- 占比 ≤1 篇/周（第四支柱）。

### ⚠️ 混写禁令（根因修复）
- 热点桶（桶1）**禁用**观点文强判断/翻案句写法。8/4 国标即事件却写翻案句，`check_prose` 5 处未清 → 返工卡住。
- 派 copywriter 不标【桶X】→ 默认套 khazix 母规范 → 热点桶混写翻案句 → `check_prose` 不过。

## 3. 文字硬约束（khazix 笔法 + 通用）

**标点铁律（khazix 母规范，三桶通用）**
- 禁中文冒号「：」→ 用逗号断句
- 禁破折号「——」→ 用逗号或另起
- 禁双引号 `" "` → 强调统一用「」
- 禁套话（说白了/意味着/本质上/不难看出/显而易见）
- 禁抽象比喻（类比须日常可感）
- 短段落自然推进，不堆砌

**日期硬约束**
- 一律阿拉伯数字带空格（7 月 28 日 / 14.1 万次），禁中文大写
- 事件发生日 ≠ 披露日；计划下达 ≠ 已实施（标阶段）
- **「今年/去年」须对应当前实际年份**（8/7 打回：HF 是 2026 年 7 月被入侵，勿写「去年」）；写相对时间先核对「发布当月 vs 事件月份」是否跨年
- 派 copywriter 时 prompt 硬约束须显式含日期数字条目（8/4、8/5 两踩）

**品牌/人称硬约束**
- ⚠️ **khazix 只是文末署名，不是号主**：正文任何位置禁自称「我是 khazix」/「这是 khazix 的号」；文末不另加 khazix 独立署名行（公众号名片已含品牌人设）
- ⚠️ 正文禁自我引用式表述（我这号/这本号/本号/我们号/号主），像模板腔；改用「我/这条线/连续剧」
- 事实严谨：二手转述禁拟人化演绎（用媒体原口径）；「全球首个」等定语写全；政策标阶段

**标题铁律**
- 动笔前给 3 组 A/B/C 用户拍板，首选 C 型（紧迫警告），15 字内
- 三原则：信息密度 / 品牌辨识 / 情绪多样
- 用户选定后写入 `metadata.json`；推送 title/digest 从 metadata 读，禁硬编码

## 4. HTML 排版铁律（零 div 单 p 整块 · 微信端）

**结构铁律**
- **零 div**：色块一律单 `<p>` 整块（background/border/padding 写在 p 上 + `<br>` 换行）。div 背景微信渲染异常（8/5-8/6 翻车根因）
- 全内联样式；无 DOCTYPE / html 注释 / ul-li / flex / gradient / grid
- font-weight 用 bold；`code` 内禁 font-size（继承 16px）
- 外层 `<section max-width:680px;margin:0 auto>` 居中（**仅 1 个 section 容器**，禁 section 嵌套 p 作背景块）
- `background-color` 代替 `background`（微信兼容写法）；ul/li → `<p>•`；linear-gradient → `<strong>`+color；引用块 → `<p>`+border-left

**标准色值表（禁自创）**

| 用途 | 背景 | 边/强调 |
|------|------|---------|
| 开头/配图锚点卡 | `#fffaf0` 浅橙 | 金边 `#f5a623` |
| 浅蓝要点卡 | `#f0f7ff` | 蓝边 `#5dade2`（带蓝色标题 span） |
| 蓝边引用块 | 透明 | 左蓝边 `#5dade2`，文字 `#555` |
| 流程图 ① | `#f0f7ff` 浅蓝 | 蓝边 `#5dade2` |
| 流程图 ②③ | `#fff5f5` 浅红 | 红边 `#e74c3c` |
| 流程图 ④结论 | `#1a1a2e` 深底 | 金边 `#f5a623`，文字 `#e8e8e8` |
| 盾块（前） | `#f0fff4` 浅绿 | 绿边 `#1e8449` |
| 矛块（后） | `#fff5f5` 浅红 | 红边 `#c41e3a` |
| 结尾两卡 | `#1a1a2e` 深底 | 金边 `#f5a623`，文字 `#e8e8e8` |
| 信源块 | 透明灰 | 上边线 `#e8e8e8`，文字 `#999999` |
| 强调色集 | — | 仅 `#c41e3a` / `#f5a623` / `#5dade2` / `#1e8449` |
| H2 章节标题 | 透明 | 红左 border `#c41e3a`，字 `#c41e3a` |

**结尾两卡（必做）**
- 深色 `#1a1a2e` + 金边，**p 必须带 `color:#e8e8e8`**（否则深字压深底看不见）
- 「写在最后」金句金色 `#f5a623`；「关注我」标题金色，第二行固定「六一的 AI 人生记录仪，一个做了快十年 AI 安全的老朋友」

**防重复标题（8/10 踩坑）**
- ⚠️ `article.html` 第一个 `<p>` **禁 22px bold 标题**：微信后台用 metadata.json 的 `title` 自动渲染头条，`article.md` 的 `# 标题` H1 在 md→html 转换时被渲染成 `<p style="font-size:22px;font-weight:bold;">标题</p>`，与头条撞车显示两次。
- **推送前必删 article.html 的第一个 22px bold `<p>`**，从浅橙导语卡开始。`article.md` 本身禁写 `# 标题` H1。

**8 项兼容自检（全 0）**：class / DOCTYPE / 注释 / flex / gradient / ul-li / grid / div 全 0；section 标签平衡（仅 1 个外层）。

## 5. 可视化层次（高密度层次 #6 · ⚠️ 易漏，必做）

> **铁律**：纯叙述平铺 = 不及格。任何一篇文章（尤其桶1/桶2）都必须套以下可视化层次，让读者一眼抓住重点。这是 8/11 用户明确指出漏掉的环节（「缺少重点标记、缺少可视化示意图」），此后每篇必查。

排版前对照模板 `article_template.html` 的 `#6 高密度层次`，逐块确认下列元素已落地：

- [ ] **红色关键词强调**：关键判断/数据用 `<strong style="font-weight:bold;color:#c41e3a;">` 红色加粗（满篇要有，不是一两个）
- [ ] **`code` 术语高亮**：专业术语用 `<code style="background:#f0f7ff;color:#c41e3a;padding:1px 5px;border-radius:3px;font-family:Menlo,Consolas,monospace;">术语</code>`（权重/蒸馏/护栏/实时监控等满篇铺，code 内禁 font-size）
- [ ] **浅蓝要点卡片**：清单/总结类内容，单 p 整块（`#f0f7ff`+蓝边 `#5dade2`，带蓝色标题 span + `•` 要点）
- [ ] **蓝边引用块**：金句/反差句，单 p（`border-left:3px solid #5dade2`，文字 `#555`）
- [ ] **流程图**：标题 p + 步骤框单 p + 箭头 p（↓），展示主论点推进；框数按需要增减；④结论用深底卡 `#1a1a2e`+金边
- [ ] **盾/矛双色对比块**：把抽象辩证变成一眼扫的对比（盾 `#f0fff4`+绿边 / 矛 `#fff5f5`+红边 `#c41e3a`）
- [ ] **结尾双深底卡**：「写在最后」（金句金色）+「关注我」（四行固定文案，品牌名不可省）
- [ ] **配图锚点块**（文中需插图处）：`#fffaf0`+金边，标题金 14px，GPT prompt 灰 `#666` 13px；推「带提示词版」保留，推「清理版」删除本块

## 6. check_prose 硬 gate

- 路径：`~/.workbuddy/skills/human-writing/scripts/check_prose.py`
- **跑 `article.md`（勿跑 html，英文 prompt 冒号会误报）**
- 硬 gate（须全 0）：翻案句 / 黑话 / 硬停词 / 模型路标
-  advisory（人工判断，不阻断）：需辨语境词、洞察路标、长前置成分、重定语句
- 用法：`python3 ~/.workbuddy/skills/human-writing/scripts/check_prose.py content/YYYY-MM-DD-slug/article.md`
- 汉字数同时核对：桶1/桶2 须 3000-3500 纯汉字；桶3 须 4000-6000 含标点

## 8. 发布工作流 v8.0 速查（8 步）

```
选题(四维+三塔+定桶；每日现定题) → angle.md(占质量60%) → 标题定稿(metadata.json)
  → 文案(copywriter+标桶+check_prose) → 封面(1280x720 先预览)
  → HTML排版(零div单p整块+可视化层次+自检) → 6.5 预览gate(硬) → 7 推送(定版→推→清旧稿) → 8 评论巡查(1-3天)
```

- **Step 6.5 预览 gate（硬 ⭐）**：列层次清单请用户核对 OK 才推，否则回头改
- **Step 7 推送命令**：
  ```bash
  env -u HTTPS_PROXY -u HTTP_PROXY -u https_proxy -u http_proxy NO_PROXY="*" \
    /opt/homebrew/bin/python3 scripts/publish/wechat_push.py --dir content/YYYY-MM-DD-slug
  ```
  （Python 内 `os.environ.pop()` 清代理，微信 API 须直连；重推前先 `draft/delete` 清旧稿防堆积；订阅号须后台手动群发）

## 9. 每篇目录结构

```
content/YYYY-MM-DD-slug/
├── metadata.json    # 标题/摘要/作者（标题唯一源，禁止硬编码）
├── article.md       # 正文 Markdown（禁写 # 标题 H1）
├── article.html     # 微信兼容 HTML 排版（零 div 单 p + 可视化层次）
├── cover.png        # 封面图 1280x720
├── angle.md         # 创意策划方案（占质量 60%）
└── research.md      # 素材调研（5 类信源，可选）
```
